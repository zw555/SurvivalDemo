# 09 · 任务与结局

## 一、功能定位

**给玩家一个明确的目标和结束的地方。**

没有目标的生存游戏，玩家的行动会退化为"漫无目的地捡东西"。
任务链提供三件事：**去哪**、**做什么**、**什么时候算完**。

## 三、本轮确认的设计决定

> 2026-10-15 用户确认：方案 A 为主（分散并加重撤离清单）

### 3.1 问题诊断（已核算，非猜测）

原清单 4 类物资的来源高度重叠：

| 清单项 | 来源建筑 |
|---|---|
| 食物 ×2 | 超市 **或** 军营 |
| 水 ×2 | 超市 |
| 汽油 ×1 | 军营 |
| 医疗 ×1 | 医院 **或** 军营 **或** 警局 |

**全部挤在超市/医院/军营三栋楼**，一趟就能收齐。最短通关路线纯移动 **18 秒**
（一天有 600 秒，只占 3%）。这是"5 分钟通关"的根本原因。

### 3.2 新清单

```gdscript
const SUPPLY_REQUIREMENTS := {
    ItemData.KIND_FOOD: 4,
    ItemData.KIND_WATER: 4,
    ItemData.KIND_FUEL: 2,
    ItemData.KIND_MEDICINE: 2,
    ItemData.KIND_AMMO: 1,      # 新增：迫使玩家去警局
}
```

### 3.3 为什么这样改

| 设计目标 | 实现方式 |
|---|---|
| 强制跑遍多栋楼 | 弹药只能从警局拿，汽油只能从军营拿 |
| 强制分多趟 | 清单合计 **13 件 > 初始背包 8 格**，一趟装不下 |
| 制造取舍 | 每趟只能带 8 格，玩家必须决定"这趟先拿哪个楼的东西" |
| 延长游戏 | 从1 趟变成 4~5 趟 |

### 3.4 任务文本同步更新

清单显示文本（第 129 行附近）必须同步：

```
旧：收集物资：食物×2 · 水×2 · 汽油×1 · 医疗物资×1
新：收集物资：食物×4 · 水×4 · 汽油×2 · 医疗物资×2 · 弹药×1
```

## 五、验收标准

### 5.1 功能验证

- [ ] 任务追踪 HUD 显示新清单（食物×4 · 水×4 · 汽油×2 · 医疗×2 · 弹药×1）
- [ ] 清单未齐备时交付，老周提示"还差着呢"并列出缺什么
- [ ] 清单齐备后可正常交付，进入汇合阶段
- [ ] **弹药只从警局获得**（其他建筑不产弹药）
- [ ] 玩家实际需要跑 **至少 4 栋建筑**才能凑齐清单
- [ ] 背包 8 格装不下 13 件时，玩家必须分趟往返仓库/安全屋中转
- [ ] 交付后 Boss 照常出现，结局流程正常
- [ ] 读档后清单进度正确恢复
- [ ] **旧存档兼容**：读档不崩溃；若旧存档物资不足，允许"接了任务但暂时交不了"

### 5.2 冒烟测试断言（必须新增）

```gdscript
# 1. 清单数量符合新值
assert(SUPPLY_REQUIREMENTS[ItemData.KIND_FOOD] == 4)
assert(SUPPLY_REQUIREMENTS[ItemData.KIND_AMMO] == 1)

# 2. 清单总量 > 单趟携带量（这是刻意设计，不是 bug）
assert(total_required > player.base_slot_count,
    "清单应大于背包容量，强制分多趟")

# 3. 缺任一项都不能交付
for kind in SUPPLY_REQUIREMENTS:
    移除一种物资
    assert(not can_deliver(), f"缺 {kind} 时不应可交付")

# 4. 齐备后可交付且正常推进任务阶段
```

### 5.3 平衡自查（执行方必须验算）

```
全图实际可获得（已核算）：
  食物 ~13 罐  → 清单要 4 → 够 3.2 趟
  水   ~9 瓶  → 清单要 4 → 够 2.2 趟
  汽油  6 桶  → 清单要 2 → 够 3.0 趟
  医疗 ~10 个 → 清单要 2 → 够 5.0 趟
  弹药 ~8 盒  → 清单要 1 → 够 8.0 趟
```

**瓶颈是水（2.2 趟）**。如果实测发现水太紧张导致经常卡关，
可考虑：把水的清单从 ×4 降到 ×3，或增加超市/其他建筑的水。
