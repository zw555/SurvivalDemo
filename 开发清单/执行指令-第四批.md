## 二、问题 1：容器面板与 Tab 合并（可直接做）

### 现状问题

`StoragePanel` 锚定在**屏幕右上角**，而任务追踪面板也在右上角。
玩家按 E 打开箱子时，箱子面板和任务追踪**重叠**，箱子里的物品信息被挡住。

### 建议改法

**采纳你的想法：合并成一个面板，左背包 + 右箱子。**

```
┌─────────────────────────────────────────┐
│ 攻击25 · 护甲3 · 移速+10%│  箱子：军需柜   │  ← 顶部
├──────────────────┬──────────────────────┤
│                  │  箱子物品│
│  玩家背包        │  [ ][ ][ ][ ][ ][ ]      │
│  （人体轮廓装备） │  [ ][ ][ ][ ][ ][ ]      │
│                  │                      │
│                  │  左键=放入背包        │
│                  │  左键=取出到背包      │
└──────────────────┴──────────────────────┘
```

**要点**：
- **容器打开时，Tab 面板自动切换到「左背包 + 右容器」布局**
- 容器未打开时，Tab 是「左装备 + 右背包」
- **任务追踪面板在 Tab 打开时自动隐藏**（或移到左下角暂避）
- 两个面板不再各自独立，**不会重叠**

### 涉及文件

| 文件 | 改什么 |
|---|---|
| `scenes/ui/HUD.tscn` | GearPanel 加一个容器区；StoragePanel 合并或改锚点 |
| `scripts/ui/hud.gd` | 容器打开时切换布局；任务追踪避让逻辑 |

### 验收标准

- [ ] 打开箱子时，箱子物品**全部可见**，不被任务追踪遮挡
- [ ] 容器布局 =左背包 / 右箱子，与 Tab 位置一致
- [ ] 存入 / 取出逻辑不变（左键放入、取出）
- [ ] 打开 Tab 时任务追踪不遮挡面板
- [ ] 关闭容器后回到「左装备 + 右背包」布局

## 三、问题 2：UI 整体放大（可直接做）

### 现状数据

```
背包格     46px
装备槽     56px
状态栏文字  默认字号
按钮       默认尺寸
```

在 1152×648 的分辨率下确实偏小。

### 建议数值

| 元素 | 当前 | 建议 |
|---|---|---|
| 背包格 | 46px | **64px** |
| 装备槽 | 56px | **72px** |
| 状态栏文字 | 默认 | 字号 **+3** |
| 面板按钮 | 默认 | **×1.3** |
| 字体全局 | 默认 | 考虑 `Project Settings → GUI → Theme → Custom Font Size` |

**建议优先用全局主题字号**，比逐个改更省事，也不容易漏。

⚠️ **注意**：放大后要检查 Tab 面板能否容纳放大后的装备 + 背包。
8列 × 64px = 512px，加上装备区约 300px = 812px，在 1152 宽度内**放得下**。

## 四、问题 3：建筑贴太近 · 地图尺度（需要你决定）

### 实测数据

| 建筑对 | 边缘间距 | 步行耗时 |
|---|---|---|
| **超市 ↔ 五金店** | **20px** | **0 秒** |
| 医院 ↔ 军营 | 40px | 0 秒 |
| 超市 ↔ 警局 | 40px | 0 秒 |
| 警局 ↔ 军营 | 250px | 2 秒 |

三对建筑几乎贴在一起。这不是"有点近"，是**刚出门就到了下一栋楼**，
完全没有"在城区穿行"的感觉。

### 三个方案

| 方案 | 做法 | 成本 | 风险 | 效果 |
|---|---|---|---|---|
| **A** 只放大 UI | 见上节 | 0.5 天 | 零 | UI 清楚了，**间距问题没解决** |
| **C** ⭐ 相机缩放 | `Camera2D.zoom = (0.8, 0.8)` | **1 小时** | 低 | 屏幕能装下 1440px 宽的世界，间距看起来远 25% |
| **B** 真正扩地图 | 2400×1600 → 3600×2400 | 2~3 天 | **高** | 根本解决 |

### 方案 C 的具体做法

**文件**：`scenes/player/Player.tscn`

```
[node name="Camera2D" type="Camera2D" parent="."]
zoom = Vector2(0.8, 0.8)      # 新增
```

**效果换算**：
- 世界在屏幕上缩小 20%
- 屏幕可见世界宽度：1152 → **1440px**（接近 1.25 屏）
- 玩家从 46px 变成 **37px**，仍看得清
- 建筑间距 20px → 屏幕上看起来 16px（配合"屏幕能装更多"整体感受改善）

⚠️ **C 的局限**：视野数值仍是 460px（屏幕上占比不变），
所以**「规避丧尸」的问题不会被 C 解决**——那个只能靠视野数值或减速丧尸。

### 方案 B 的风险（为什么建议先别做）

要改的地方比想象多：

| 需要改 | 说明 |
|---|---|
| `Main.tscn` 全部墙体坐标 | 建筑 + 内部隔断 + 门 + 家具，约 30+ 处 |
| `map_size` | 2400×1600 → 3600×2400 |
| 导航网格烘焙 | 地图变大后导航需要重新验证 |
| 迷雾数组 | 按网格尺寸计算 |
| `MAP_BUILDINGS` 坐标 | 6 处地点标记 |
| **冒烟测试硬编码坐标** | **约 15+ 处测试直接写了坐标**，改地图会全部失效 |

**改错一个坐标的后果**：玩家卡在墙里、导航失效、测试红一片。
对 0 基础独立开发者来说，**这是本项目目前最大的一块技术债**。

### 我的建议

**先做 C + A，验证核心循环之后再决定要不要上 B。**

理由：
1. **你现在最缺的是实测数据，不是更大的地图**
2. 如果核心循环验证通过（玩家确实在做取舍），说明方向对，再花两天扩地图不迟
3. 如果核心循环没成立，**扩到 10 倍大也没用——问题不在地图**
