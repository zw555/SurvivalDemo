# 16 · 医疗伤势与疾病

## 一、功能定位

**让"受伤"变成一个需要处理的长期状态，而不只是掉一格血。**

一次性掉血是瞬时的，玩家学会"血少了就吃药"就没什么可玩。
伤势与疾病把受伤拆成了一条链条：**受击出血 → 未处理则感染 → 感染引发发热**，
每一步都需要不同的药，��且治好了还要等恢复时间。

## 二、当前状态

✅ **已完成**（2026-10-15，348 项测试通过）

## 三、设计规则（已确定）

### 3.1 状态类型

| 类别 | 状态 | 效果 |
|---|---|---|
| **伤势** | 轻度出血 | 0.15 伤/秒，6 游戏小时可自愈 |
| | 严重出血 | 0.6 伤/秒，**不处理可致死** |
| | 骨折 | 移速 ×0.55，奔跑精力 ×1.6，疲劳 ×1.3 |
| **疾病** | 伤口感染（三级） | 精力上限 −10/−15，恢复 ×0.85/0.75/0.65，最高级 0.3 伤/秒+ 10% 落空 |
| | 发热 | 恢复 ×0.8，疲劳 ×1.25，冷却 ×1.15 |
| | 肠胃疾病 | **水耗 ×1.5、食物 ×1.2**，移速 ×0.85 |

### 3.2 触发链条（有来源，无随机）

```
受击（伤害≥25）→ 40% 严重出血 / 30% 轻度出血
单次伤害 ≥18→ 30% 骨折
出血未消毒 → 每小时累积感染风险（轻度 4% / 严重 8%）
感染 → 发热（感染降级后 3 小时自行消退）
脱水持续 60 游戏秒 → 肠胃疾病
```

**关键设计**：没有"无缘无故生病"。每个状态都有可追溯的原因，玩家能理解并预防。

### 3.3 医疗物品规则（8 种，边界明确）

| 物品 | 规则 |
|---|---|
|绷带 | 止血：轻度直接处理；严重仅降级为轻度（**有限缓解**）|
| 夹板 | 骨折固定：移速 ×0.8，24 游戏小时痊愈 |
| 急救包 | 生命 +70，可止住严重出血 |
| 消毒剂 | 清除感染风险，6 小时内不累积 |
| 抗生素 | 逐步治愈感染（9 游戏小时）；**对骨折/出血/发热无效** |
| 止痛药 | 1 小时内骨折惩罚减半（**不治疗伤势本身**） |
| 退热药 | 2 小时内缓解发热（**不治愈根源感染**） |
| 补液盐 | 治疗脱水/肠胃 |

**设计亮点**：止痛药/退热药只"缓解"不"治愈"，且**有时限**。
玩家会面临"我没有抗生素，但有止痛药，先撑着还是冒险去找抗生素"的决策。

### 3.4 架构约束（重要）

**采用「读取时算修正值」模式**，与精力疲劳一致：
- 各状态只声明自身修正值
- 状态解除后修正自动消失
- **绝不改写基础属性**

所有修正走统一接口，已接入：移速、攻击力、攻速、落空率、奔跑精力消耗、
食水消耗、精力上限。

## 六、⚠️ 发现的问题（需用户决策）

### 问题 1：与本轮「消耗×3」方案叠加过重

**已核实**：`player.gd:732-733` 的消耗计算是

```gdscript
water = maxf(0.0, water - water_drain_per_sec * medical.water_drain_mult() * delta)
```

本轮计划把`water_drain_per_sec` 提到 **0.5/s（×3）**，而肠胃疾病再乘 1.5：

| 状态 | 实际水耗 | 满状态100 撑 |
|---|---|---|
| 正常（本轮×3 后） | 0.5/s | 200 秒 ≈ 3.3 分钟 |
| **得了肠胃疾病** | **0.75/s** | **133 秒 ≈ 2.2 分钟** |

**后果**：玩家一旦脱水得肠胃病，生存窗口反而更短——这在逻辑上说不通
（生病应该更难救，而不是更快死）。

**可选方案**：

| 方案 | 做法 | 代价 |
|---|---|---|
| A | 消耗×3 时，肠胃倍率改成 **除以** 或降低 | 削弱疾病威胁 |
| B | 消耗×2 而不是 ×3，保留肠胃 ×1.5 | 整体压力下降 |
| C | 保持现状，但让肠胃病**可治愈且容易**（补液盐 plentiful）| 医疗重要性上升 |

**倾向C**：疾病系统本轮刚做，先不做大改。等实测后再定。

### 问题 2：第三套惩罚系统

现在玩家同时承受三套：
1. 饥饿 / 口渴（生存压力）
2. 精力 / 疲劳（行动限制）
3. 伤病 / 疾病（长期负担）

**风险**：三套同时压，玩家可能只觉得"一直在掉血一直在饿"，
反而**感知不到核心的取舍乐趣**（带多少食物、走多远、何时回）。

**建议**：本轮**不叠加第四套惩罚**。新功能排期时先问"它增加了决策还是只增加了烦躁"。

### 问题 3：8 种药目前无建筑产出（已核实）

新增的夹板/消毒剂/抗生素/退热药/补液盐**只进了掉落表**
（`box_table.tres` + `rich_table.tres`），**没有任何建筑容器产出它们**。

医院急救柜与床头柜仍是旧的三种药（绷带/止痛药/急救包）。

**后果**：
- 医疗来源没有分化——想去医院拿抗生素，拿不到
- 撤离清单的「医疗 ×2」如果用绷带就能满足，**这些新药与核心循环脱钩**
- 箱子和市中心富表出药，意味着医疗变成了"运气活"而非"目的地"

**建议（需用户确认）**：

| 方案 | 医院放什么 | 箱子/富表放什么 |
|---|---|---|
| A· 分化 | 抗生素、消毒剂（专用药） | 绷带、止痛药（通用药） |
| B · 通用为主 | 保留绷带为主| 保持现状 |
| C · 清单牵引 | 清单要求「抗生素×1」，逼玩家去医院 | 其他药仍可掉落 |

**倾向C 或 A**：让医疗来源与撤离清单挂钩，才能形成"必须去医院"的理由。
