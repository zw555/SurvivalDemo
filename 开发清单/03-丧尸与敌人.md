# 03 · 丧尸与敌人

## 一、功能定位

**提供"出门的风险"和"战斗的成长感"。**

丧尸不是敌人，是**会动的资源消耗成本**。玩家为了拿东西必须穿过它们，
所以它们的密度和强度，直接决定每次搜刮的代价。

## 二、当前状态

🔧 **本轮要改**（提高守卫密度）

当前实现：4 种敌人（普通/迅捷/强壮/Boss）+ 完整感知行为（视线/听觉/记忆/寻路）
+ 自主行为（游荡/搜索/调查）。

## 三、本轮确认的设计决定

> 2026-10-15 用户确认：方案 B 为辅（提高建筑守卫密度）

### 3.1 为什么调整

当前一栋楼 3~6 只丧尸、2~4 分钟就能搜完。
配合"物资只在建筑内"的新规则，玩家每趟的成本太低，
仍然会出现"冲进去搜刮然后撤离"的快节奏玩法。

**目标**：每趟搜刮从 3 分钟延长到 6~8 分钟。

### 3.2 守卫数量调整

| 建筑 | 当前 | 建议 | 理由 |
|---|---|---|---|
| 超市 | 3 | **5** | 主食物源，必须最危险 |
| 警局 | 3 | **4** | 弹药唯一来源 |
| 医院 | 3 | **4** | 医疗来源 |
| 五金店 | 3 | **3** | 维持（材料不是刚需） |
| 军营 | 6 | **6** | 维持（终局区域） |
| 室外散点 | 6 处× 1~2 | 维持 | 不变 |

⚠️ **注意**：具体数值由执行方**实测决定**。上表是起点，
目标是让每栋楼的搜刮时间达到 6~8 分钟，而不是死守数字。

### 3.3 分布要求（比数量更重要）

⚠️ **守卫不能集中在一处**。

现在的配置（`MarketGuard` 等）会把 3 只丧尸刷在同一个点附近，
玩家进门就会被围殴。**应该把守卫分布到不同区域**，
让玩家能一个区域一个区域地清理，有喘息的节奏。

执行方需检查每个 `SpawnPoint` 的 `spawn_radius`（当前 60px），
并考虑拆成多个生成点分布在建筑不同角落。

### 3.4 不要改的东西

以下已完成，**本轮不要动**：
- 感知模型（视线 + 听觉 + 记忆）——已实测合理
- 自主行为（WANDER / SEARCH / INVESTIGATE）——已完整
- 导航寻路——已解决绕墙问题
- 四种敌人的数值配比——已审计平衡
- Boss 三阶段行为——已实现且有可躲前摇

## 五、验收标准

### 5.1 功能验证

- [ ] 超市守卫达到 5 只左右
- [ ] 警局、医院守卫达到 4 只左右
- [ ] 五金店、军营数量维持
- [ ] 室外散点丧尸数量**完全没变**
- [ ] **守卫分布在建筑不同区域**，不是挤在一处
- [ ] 玩家能在超市里找到相对安全的角落喘息
- [ ] 每栋楼实际搜刮时间实测 6~8 分钟
- [ ] 新手不会因为进门被围而毫无还手之力（保留撤退路线）
- [ ] Boss 行为不受影响（仍驻守停机坪，不游荡）

### 5.2 冒烟测试断言（必须新增）

```gdscript
# 1. 各建筑守卫数量
assert(get_zombie_count_in(MARKET) == 5)
assert(get_zombie_count_in(POLICE) == 4)
assert(get_zombie_count_in(HOSPITAL) == 4)

# 2. 室外丧尸总数不变（回归保护）
assert(outdoor_zombie_count == 修改前的数值)

# 3. 守卫分布（不全部集中在一个点）
assert(守卫之间的最小距离 > 某阈值,
    "守卫不应全部挤在同一位置")

# 4. Boss 仍驻守
assert(brute.can_wander == false, "Boss 不应游荡")
```

### 5.3 平衡自查（执行方必须实跑测量）

**测量方法**：从安全屋出发，跑到每栋楼，计时完成
"进入 → 清理/躲避全部守卫 → 搜刮完所有容器 → 离开"。

记录每栋楼耗时，填入：

| 建筑 | 目标耗时 | 实测耗时 | 是否达标 |
|---|---|---|---|
| 超市 | 6~8 分钟 | | |
| 警局 | 6~8 分钟 | | |
| 医院 | 6~8 分钟 | | |

若某栋楼实测超过 10 分钟（玩家会觉得"磨"），下调该楼守卫数量。
